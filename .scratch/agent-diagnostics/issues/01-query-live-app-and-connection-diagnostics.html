Summary

An agent can discover AFKtor's authenticated localhost API, read a versioned current-state snapshot, and page through startup and connection-change events. The Windows app starts and stops the service automatically; Linux tests exercise the same real host without WinForms or League. This slice provides bounded live/current-run evidence; durable prior-run history follows in ticket 02.

Agent diagnostics design · Ticket index and review workflow

Acceptance criteria

  • Starting the Windows app automatically starts a read-only local diagnostics service; a Linux test host starts the same service without WinForms or League. Query the actual listener to verify run/build identity, schema version, ordered current-run events, timestamps, and a coherent connection snapshot with a sequence watermark.
  • Capture app startup/shutdown and connection changes at their source. Uninstrumented fields are explicitly unavailable; do not fabricate ready-check details or infer event history by polling display strings.
  • Bind only to 127.0.0.1 on an assigned port and generate a fresh bearer token of at least 256 bits. A per-instance discovery descriptor exposes the bound endpoint, run ID, version, and token only to the current OS user. Publish it after successful startup, remove it on normal shutdown, and provide a way to reject stale descriptors by run identity.
  • Missing or incorrect credentials and unsupported methods are rejected. The API has no arming, acceptance, settings-edit, League-proxy, or remote-listening capability; no CORS access is enabled. Agents can fetch current state and events using a documented, versioned read contract.
  • Declare finite limits for memory history, producer work, event detail, queueing, pagination, response size, concurrent requests, request deadlines, and error metadata. Pagination returns sequence/cursor and completeness information; distinguish history eviction or dropped events from an empty tail and report truncation explicitly.
  • Collector/API startup errors, backpressure, throwing or hung sinks, and missing discovery access cannot block startup, ready-check operation, cancellation, discovery, or exit. Producer calls perform no formatting, disk/API I/O, or user callbacks inside scheduling locks. Diagnostic shutdown is capped at two seconds; degraded health and losses remain observable through usable channels.
  • Linux integration tests cover the real HTTP listener, authentication/discovery, connection changes, ordered pagination, invalid input, lifecycle, bounds, secret exclusion, and fault isolation. Keep the existing application tests passing and cross-compile the Windows Release target with zero warnings/errors.
  • Document agent discovery/query examples, data-contract semantics, and the runtime/deployment implications of the Kestrel host. State that a live Windows localhost endpoint is not automatically accessible to a cloud/Linux agent. Complete a separate subagent code review and record test evidence and pending native checks.
