Summary

An agent can distinguish missing or inaccessible League discovery data, invalid connection information, settings fallback/save errors, and HTTP/WebSocket/session failures, then follow recovery through the same state/event API. Rich safe evidence must preserve the existing app behavior and credential boundaries.

Agent diagnostics design · Ticket index and review workflow

Acceptance criteria

  • Expose safe discovery outcomes that distinguish client absence, inaccessible process/lockfile information, invalid/stale connection information, and successful discovery when the evidence permits. Do not turn unknown causes into confident classifications or record lockfile contents.
  • Record settings load/default/save outcomes, effective delay changes and their reasons, and failures without changing save-before-apply ordering or persisting arming. Differentiate known fallback causes where safely observable.
  • Record HTTP/WebSocket/session stages and outcomes, subscription/seed ordering, session replacement, stream loss, retry/recovery and shutdown. Include correlation identifiers, method/fixed route, status code, duration, typed safe failure category, and safe stack frames when available. Missing symbols or unobservable causes remain explicitly unavailable.
  • Sanitize evidence before collection. Secret-marker tests verify that passwords, lockfiles, authorization values, raw authenticated response bodies, diagnostic tokens, unchecked exception messages, and machine-specific absolute paths never reach snapshots, event history, or API errors. The diagnostic token appears only in its restricted descriptor/authentication handling.
  • Coalesce unchanged discovery polls and repeated identical failures with counts and first/last times; keep rich transition evidence bounded. Diagnostic health and gaps are visible without recursively generating more failures.
  • Instrumentation does not change discovery/retry cadence, loopback-only LCU destinations, connection-generation checks, settings save-before-apply behavior, arming, once-only acceptance, or cancellation policy. Diagnostic exceptions/backpressure remain isolated from these paths.
  • Linux tests query actual instrumentation through the API using controlled discovery/settings failures and simulated or real loopback transport. Verify safe failure classification, stage/seed-event ordering, timing/correlation, recovery, coalescing, secret exclusion, and continued operation with failing diagnostics. Native Windows process discovery and installed League are not required for these tests.
  • This ticket depends only on the live query slice: evidence is independently demonstrable through current-run memory/API. The generic retained-history slice must also store/query these records unchanged when integrated.
  • Update the agent troubleshooting workflow and native Windows/League acceptance checklist. Keep the existing suite green, cross-compile the Windows target where integration changes, complete a separate subagent code review, and record validation limits accurately.
