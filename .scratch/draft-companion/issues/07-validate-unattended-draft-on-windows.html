Summary

A release acceptance record establishes what actually works with native UI and the installed League Client, including consecutive matches and intervention.

Acceptance criteria

  • Run repository build and tests, then native Windows and supported live-client checks. Record client version, queue ID, settings, observed outcomes, and evidence; mark unavailable checks as blocked rather than passed.
  • Verify armed acceptance through role-specific ban/pick completion and staying armed for the next match; app restart remains disarmed.
  • Verify live edits during draft, teammate pick protection, exhausted plans, all manual-pick policies, manual-ban takeover, and default/advanced timing.
  • Verify League restart/disconnect, mid-draft enable/reconnect observing only, disarm/shutdown cancellation, and no replay of old writes.
  • Confirm diagnostics explain choices without credentials and failures in diagnostic storage do not block automation.
  • Address discovered regressions with focused reproduction; document remaining limitations and release readiness without treating simulation as live evidence.
