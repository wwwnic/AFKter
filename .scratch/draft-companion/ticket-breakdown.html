Draft companion: approved ticket breakdown

November 7, 2026. Breakdown approved; all seven tickets are published individually. Tickets 01–04 are implemented and reviewed, with native acceptance pending and draft writes gated off; tickets 05–07 have not started. Implementation is paused for the player to review usage. Source: approved design. Blocking relationships determine which tickets can start.

See the two-ticket checkpoint and verification limits and the ticket 03 checkpoint and ticket 04 checkpoint.

01: Observe supported drafts without taking action

Blocked by: None.

What it delivers: The player can see supported draft status, assigned role, local action windows, and why automation is observing only. Agents can inspect the same state through existing diagnostics.

  • Verify installed-client queue IDs, role assignment, action identity, timer semantics, teammate pick intent, and draft lifecycle using authoritative API references and replay fixtures. Record which observations still need native verification.
  • Expose draft/role/action/admission status in the tray and bounded read-only diagnostics. Keep the observer independent from UI and retain existing acceptance behavior.
  • Show unsupported queue, unknown role, ended draft, and disconnected states without draft writes.
  • Enabling or reconnecting mid-draft is observe-only until a demonstrably new draft. Disarming cancels session work; enabled state persists across matches but not app restarts.
  • Verify duplicate/out-of-order events, fresh-state admission, and session replacement with deterministic tests; demonstrate a read-only draft progression.

02: Edit and autosave role plans live

Blocked by: None.

What it delivers: The player can build and reorder pick and ban priorities for each role, with immediate effective changes, automatic persistence, and visible save failure status.

  • Provide a modest native plan editor with champion identification, ordered lists, empty plans, and no Apply button. Record the champion catalog source and update/failure behavior.
  • Publish one immutable revision per complete edit; do not publish unfinished drags or invalid input. Persist coherent revisions without delaying their in-memory effect.
  • Expose current effective revision and persistence health through the UI and existing diagnostics.
  • Failed saving leaves the latest in-memory plan effective and visibly unsaved; retry and restart recovery are verified. Malformed stored data cannot create arbitrary plans.
  • Demonstrate rapid editing, reorder, failure/recovery, and reopening the app. Verify these behaviors without a League client.

03: Complete planned bans while protecting teammate picks

Blocked by: 01, 02.

What it delivers: An admitted armed draft uses the assigned role's first eligible ban, skips teammates' intended picks, and explains exhausted plans.

  • Complete a narrow end-to-end path from live plan through decision, LCU action, observed outcome, tray status, and diagnostics.
  • Skip unavailable/already banned candidates and teammate pick intent, including intent changed immediately before dispatch. A teammate's same ban selection alone does not protect the champion.
  • Re-evaluate live revisions and eligibility before dispatch; serialize requests per action and reconcile ambiguous outcomes instead of blindly retrying.
  • External manual ban selection ends ban automation for the draft. Distinguish own acknowledgments; ambiguous attribution yields to manual control. No ban watchdog.
  • Exhaustion logs and does nothing; later changed eligibility or a new plan can provide an option. Completed bans are not revised.
  • Define and test a modest default ban pacing rule with an urgent deadline path; cancel on disarm, disconnect, or action/session end.

04: Hover and lock planned picks, respecting manual takeover

Blocked by: 01, 02.

What it delivers: The app hovers the first available planned pick, locks with deliberate pacing, and defaults to locking the current hover at the deadline after a manual pick change.

  • Use the assigned role's latest ordered plan, with no invented fallback. Expose current selection, countdown, takeover, skipped/exhausted reasons, and observed outcome in status and diagnostics.
  • Choose documented numeric defaults for normal timing and urgent request margin, grounded in client timer evidence. Skip avoidable waits when admitted actions begin late; never write after expiry.
  • Recheck revision, eligibility, action identity, enabled state, and deadline before dispatch. Cancel superseded queued work; reconcile requests already sent before issuing another.
  • Manual hover changes pause normal pick automation for the draft. Own hover acknowledgments do not cause takeover; ambiguous attribution yields. The default watchdog only locks the current valid hover, even outside the plan.
  • A live plan edit may replace an automatic hover but does not exit manual-control mode. Repeated updates/edits cannot indefinitely reset deadlines or create concurrent requests.
  • Verify normal and urgent flows, invalid hover, exhausted plan, editing races, external changes, request ambiguity, cancellation, and completed picks with a simulated clock and client.

05: Choose the deadline behavior after a manual pick change

Blocked by: 04.

What it delivers: The player can choose Lock current hover (default), Use my role plan, or Do nothing, with live application and autosave.

  • Place the explained policy in main automation settings, using existing persistence and revision handling.
  • Plan fallback selects and locks the first eligible current planned champion even when replacing a manual hover. Exhaustion logs and does nothing.
  • Current-hover fallback never substitutes a champion if that hover is invalid. Do nothing stops both selection and watchdog actions after manual takeover.
  • A policy edit during countdown affects pending work; disarm cancels all policies. Completed/dispatched actions follow the documented irrevocability boundary.
  • Verify all policies, live switches, reload persistence, and explanations in UI/diagnostics.

06: Customize timing with live advanced settings

Blocked by: 03, 04.

What it delivers: Default timing remains sufficient, while advanced users can change timing and restore author defaults without an Apply button.

  • Expose supported timing controls and bounded valid ranges, with defaults inherited from executed ban/pick behavior. Explain normal pacing and urgent deadline priority.
  • Publish valid edits immediately and autosave; invalid transient input preserves effective settings. Reset restores defaults as one coherent revision.
  • Re-evaluate pending draft work from original action timing, never extend the action deadline or revive finished/expired actions.
  • Extend existing ready-check delay handling to live edits from the original check-detection time: shortening past elapsed delay starts verification; lengthening moves the undispatched countdown. Do not revive previously skipped checks or resend accept attempts.
  • Update existing acceptance documentation/tests to make this reviewed contract change explicit. Preserve starts-disarmed and one-attempt behavior.
  • Verify live edits at dispatch boundaries, zero/maximum timing, persistence failure, reset, and observable countdown/status consistency.

07: Validate the unattended queue-to-draft journey on Windows

Blocked by: 03, 05, 06.

What it delivers: A release acceptance record establishes what actually works with native UI and the installed League Client, including consecutive matches and intervention.

  • Run repository build and tests, then native Windows and supported live-client checks. Record client version, queue ID, settings, observed outcomes, and evidence; mark unavailable checks as blocked rather than passed.
  • Verify armed acceptance through role-specific ban/pick completion and staying armed for the next match; app restart remains disarmed.
  • Verify live edits during draft, teammate pick protection, exhausted plans, all manual-pick policies, manual-ban takeover, and default/advanced timing.
  • Verify League restart/disconnect, mid-draft enable/reconnect observing only, disarm/shutdown cancellation, and no replay of old writes.
  • Confirm diagnostics explain choices without credentials and failures in diagnostic storage do not block automation.
  • Address discovered regressions with focused reproduction; document remaining limitations and release readiness without treating simulation as live evidence.

Dependency rationale

01 and 02 can start independently. Both execution slices need observed draft state and live plans, but bans and picks do not inherently block one another. Any shared coordination work stays minimal in the first slice that needs it. 05 extends pick takeover; 06 needs working pick and ban timing; 07 integrates the complete journey. Each behavior ticket includes its own tests, status, and diagnostics rather than postponing those layers to separate tickets.
