04: Separate monitoring lifetime from window lifetime

Status
needs-triage
Blocked by
None

Summary

Extract the existing application runtime while keeping the current WinForms host operational, so the later shell switch does not rewrite automation.

Source: approved design · implementation plan.

Acceptance criteria

  • Own one catalog, plan service, controller, monitors, transport and diagnostics independently of windows; preserve current paths, timing subscription and both closed native draft-write gates.
  • Retain discovery behavior and a two-second wait after each completed refresh cycle, without overlapping refresh work or blocking the UI on network/disk.
  • Expose current immutable/status evidence for rendering and explicit arm/start/stop operations. Opening or closing existing windows must not recreate application services.
  • Start disarmed. Explicit shutdown cancels held requests, drains monitors/refresh, attempts the latest plan save and disposes resources once even on repeated/concurrent requests.
  • Controlled runtime tests, the full existing suite and Release cross-build verify unchanged acceptance/settings/diagnostic behavior before the new shell replaces the old one.
