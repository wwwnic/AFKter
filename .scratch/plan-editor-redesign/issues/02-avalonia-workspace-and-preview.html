Summary

Deliver the shared production editor views and a runnable isolated preview, with all five roles, an always-browseable catalog, and straightforward click/keyboard editing.

Source: approved design · implementation plan.

Acceptance criteria

  • Show five labeled role rows with ranked picks/bans, visible names, a persistent alphabetic catalog, partial-name search and optional role filtering. Blank search supports discovery immediately. Use a compact heading, readable names without repeated initial badges, and single-line ranked lanes with counts and obvious overflow.
  • Label the catalog filter “Browse by role” separately from “Add to: role · list” above the results, paired with the selected lane outline. Clearly highlight the selected destination without relying on color alone. Catalog clicks append there; duplicates reveal their existing entry. Earlier/Later/Remove and keyboard alternatives use the same domain operations.
  • Search/filter/destination and stable selection survive presentation refresh. Catalog role filters do not reset when the plan destination changes.
  • Show truthful Saved/Saving/unsaved failure status with Retry. Effective plans remain visible through failure, and ordinary users are not shown technical revision numbers. Transient action/duplicate feedback never replaces persistent save status; duplicate feedback identifies the existing role/list/position.
  • The Linux preview runs actual shared views against isolated sample/local data without League discovery or production profile access. No image download, browser runtime or paid UI component is required.
  • View-model/headless tests and a native Linux preview check cover discovery, invalid role metadata, duplicate selection, resize/overflow, focused input and save recovery.
