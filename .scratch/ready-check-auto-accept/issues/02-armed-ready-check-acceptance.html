Summary

Arm AFKtor from the tray to have it accept an eligible League ready check after a 3-second delay.

AFKtor v1 spec

Acceptance criteria

  • AFKtor starts disarmed and sends no accept request for a ready check detected while disarmed.
  • While armed, a new pending ready check schedules one accept. Verify that AFKtor sends exactly one request after the delay, even if the pending event repeats, and only if the same check remains pending on the current connection.
  • Declining in League, expiration, disarming, or losing the connection before the deadline prevents the scheduled accept.
  • Restarting League preserves arming and discards pending work from the old connection. The next eligible check is accepted once. Restarting AFKtor resets arming.
  • Verify the ready-check events and accept route with the installed client. Use simulated events and a controllable clock to verify duplicate events and cancellation.
