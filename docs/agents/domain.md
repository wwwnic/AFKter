# Domain Docs

AFKtor uses a single domain context. Before exploring domain behavior, read the root `GLOSSARY.md` and any relevant architecture decision records (ADRs) under `docs/adr/` when they exist.

Use glossary terms consistently in specs, tickets, code, and tests. Surface conflicts with existing ADRs and explain why a decision may need revisiting. Create the glossary when the first term is settled and add ADRs as decisions warrant them.
